# 算法与色彩管线

当前算法`printroom-density-v6`。本文是公式、单位和常量的规范来源；交互见[interaction.md](interaction.md)，持久化与迁移见[architecture.md](architecture.md)。数值契约、工程默认与实际验收须区分，本文不将规范要求视为已执行的测试。

## 1. 阶段与表示

```text
L0 原始线性 RGB
 → CMOS Matrix → L1
 → Linear Gain → L2
 → Cineon Density → D0
 → Print Density Matrix → D1
 → Film Base Offset + User Timing → D2
 → RGB Contrast → D3
 → Cineon Log LUT（逐帧选择） → Final（P3-D65 Gamma 2.6 编码 RGB）
 → 齿孔白色合成（可选，仅裁剪框外）
 → 显示器色彩转换 / 导出 profile 转换
```

CPU 参考和 Metal 基线都用 Float32。L0/L1/L2 是线性透射率数值；D0–D3 **统一保存归一化密度** `N`。UI Timing 与校准偏移保存 CV，进入计算时除以 1024。函数与字段名必须标明 `CV`、`Density` 或 `NormalizedDensity`，避免混用。

中间阶段不量化为整数 CV、8-bit 或 16-bit，不把密度数组包装成普通 RGB 交给 ICC 处理。Float16 只允许在后续通过误差验收后作为明确优化。

## 2. 输入读取与解释

支持的初始输入是 3 通道无符号 16-bit RGB TIFF，`L0 = uint16 / 65535`。先解压读取样本数值，不做 ICC 转换或 transfer 解码。无 alpha；不支持的灰度、浮点、带 alpha 或其他样本格式先明确报错，不静默转成 8-bit。

输入解释固定记录为：原色 P3-D65，transfer Linear。最终工作显示 profile 使用现有 `ICC/DCIP3_D65.icc`。

**资产实测差异：**10 张参考 TIFF 实际嵌入 `ProPhoto RGB Linear`，三个 TRC 均为 Gamma 1.0。按用户“指定/解释，保持数值”的要求，初始模式仍将这些原始通道数值解释为 P3-D65 Linear，不执行 ProPhoto→P3 转换。保留原 ICC 名称和哈希作为诊断；界面中的呈现按 [interaction.md](interaction.md) 决定。这是一项明确的数值处理约定，不宣称保留嵌入 profile 定义的原始色度。

不新增“自动按 ICC 转换”模式。未来如果引入真正的输入原色转换，必须成为独立算法策略和项目字段，不能改变旧项目结果。

## 3. 片基采样与 Linear Gain

选区映射到完成 TIFF orientation 校正后的原始像素坐标，整数边界，左上包含、右下不包含。保存此坐标空间、来源帧 ID、图像尺寸与选区。TIFF读取原片选区，RAW按下文代理采样契约读取。先对选区每个原始 RGB 像素应用当前 CMOS 矩阵，再求逐通道中位数；不能以矩阵乘原始通道中位数代替。偶数样本数取中间两值平均，禁止先取 RGB 亮度再求中位数。

工程默认：选区至少 16 个有效 RGB 像素；排除任何通道非有限的整个像素。任一通道中位数 `base[c] <= 0` 则校准失败，保留已有有效校准。核心保留零值和饱和样本比例诊断，不暗中排除有限亮暗值；日常界面不计算或显示这组诊断。

```text
gain[c] = 0.75 / base[c]
L1 = CMOS × L0
base[c] = median(L1 samples[c])
L2[c] = L1[c] × gain[c]
```

未校准时 gain=(1,1,1)、offsetCV=(0,0,0)，状态为未校准；主预览和缩略图直接显示未处理的L0代理，不经过CMOS、Gain、密度、Timing、Contrast或LUT；无片基时不计算处理阶段直方图。导出既有公式保持。不裁切 L1 或 L2 上界；大于 1 可以形成负密度。

## 4. 密度与 CV

```text
physicalDensity = -log10(T)
normalizedDensity = physicalDensity / 2.048
physicalDensity = CV × 0.002
normalizedDensity = CV / 1024
CV = normalizedDensity × 1024
```

工程默认：`T = max(L2, 1e-6)`；零值和有限负值被替换并累计诊断计数。NaN/Inf 不送入 LUT：处理任务返回明确错误，保留上一次有效预览并禁止本次导出。不裁切有限的中间密度。

| 参考点 | CV | 实际密度 | 归一化密度 |
| --- | ---: | ---: | ---: |
| 黑点/片基校准目标 | 95 | 0.19 | 0.0927734375 |
| 18% 中灰参考（旧版 pivot） | 470 | 0.94 | 0.458984375 |
| 白点参考 / 当前反差 pivot | 685 | 1.37 | 0.6689453125 |

这些参考点不代表必须在基础 `-log10(T)` 中额外加入 Cineon 黑位、白位或曝光曲线。白点不是内部裁切点。

**1024/1023 工程决定：**本版本严格使用上述 1024 约定，D3 直接送 LUT，不附加 `1024/1023` 缩放。普通 10-bit 文件的 `code/1023` 不得混入本管线。文件头仅说明 Cineon Log 0–1，无法证明作者精确采用了哪种归一化或扫描标定；当前衔接是待视觉与色阶验证的工程约定。若证据要求调整，创建算法新版本，禁止无声更改已有项目。

## 5. Transform to Print Density

提供只读 `identity`、`ledLightSource` 和用户手动输入的自定义 3×3 系数；新卷选择LED Light Source，旧卷沿用保存值。内置值不可编辑或删除，自定义系数不自动归一化。RGB 列向量，左乘矩阵，计算发生在归一化密度域：

```text
D1 = M × D0

Identity =
[ 1  0  0 ]
[ 0  1  0 ]
[ 0  0  1 ]

LED Light Source =
[  1.0584  -0.0204   0.0023 ]
[  0.0753   1.0120  -0.0693 ]
[ -0.0147   0.1420   0.7774 ]

R′ =  1.0584R − 0.0204G + 0.0023B
G′ =  0.0753R + 1.0120G − 0.0693B
B′ = −0.0147R + 0.1420G + 0.7774B
```

来源：用户提供的矩阵截图及 RGB 顺序确认。无额外矩阵偏移。内置密度矩阵不得归一化行和、转置、拟合或修改系数；用户新增矩阵按输入值应用。Swift SIMD 矩阵可能按列构造，须用基向量验收其实际乘法方向。

## 6. 片基 95 CV 自动校准

```text
baseL2 = base × gain
baseD0 = -log10(max(baseL2, epsilon)) / 2.048
baseD1 = M × baseD0
filmBaseOffsetCV = (95,95,95) − 1024 × baseD1
```

offsetCV 保留浮点。含义是让 `baseD1 + offsetCV/1024` 达到片基目标；偏移作用在 D1 之后。D1 本身不含偏移，D2 同时包含自动偏移和用户 Timing。校准承诺仅在用户 Timing=0、Contrast=1 的基准状态成立，后续手动调色可以移动片基。

用户框选片基时，使用当时 CMOS 处理的选区中位数及当时密度矩阵计算 gain 和 offset。已校准卷应用新 CMOS 矩阵时沿原片选区重新逐像素处理并取中位数，更新 base/gain/offset；只改密度矩阵时保留 base/gain，按新矩阵重算 offset。若旧项目当前 CMOS 与采样 CMOS 不同，改密度矩阵也先重新采样，确保对齐成立。未校准卷仍 gain=1、offset=0。仅编辑或删除库预设不改变卷快照。已存片基是卷级数值快照，不因来源缺失、指纹/RAW处理身份变化而失效，也不提示复核。密度矩阵重新对齐使用已存base/gain；CMOS切换仍按原选区读取当前源图像逐像素重新采样。重新采样时来源缺失、选区尺寸不匹配或采样失败则整次应用失败，保留原矩阵和校准；连续矩阵请求合并最新目标并丢弃过期结果。矩阵和校准一起提交、一起撤销，保留每帧 Timing/Contrast。保存/重开仍只验证已存采样快照，不主动重算，因此旧项目打开时画面保持。

## 7. Timing 与 RGB Contrast

```text
effectiveCV[c] = filmBaseOffsetCV[c] + masterCV + channelCV[c]
D2[c] = D1[c] + effectiveCV[c] / 1024
```

Master、R、G、B 默认为 0，用户控件各自为整数 `[-512,512]`，基础步进 1 CV（快捷键连续行为见 [interaction.md](interaction.md)）。各控件限制独立，合成偏移不再裁切到该范围。正值代表密度增加，不先按最终亮暗视觉反向解释。

```text
pivot = 685 / 1024
finalContrast[c] = masterContrast × channelContrast[c]
D3[c] = pivot + finalContrast[c] × (D2[c] − pivot)
```

反差默认均为 1。用户指定每个控件可调范围 `[0.25,2.0]`，步长 0.01，允许数值输入；乘积不再次裁切。为保持旧项目外观，读取、复制与计算仍兼容旧范围至 4.0，不自动裁切已保存值；控件重新输入或拖动时限定至 2.0。pivot 固定为 685 CV（Cineon 参考白点），不可编辑；界面中的呈现按 [interaction.md](interaction.md) 决定。旧项目兼容见§13。

## 8. LUT

原始表为`LUT/`中的两份33³电影表。运行使用`assets/DerivedLUTs/diffuse-white-v1/`中的两份65³派生表，DOMAIN_MIN=(0,0,0)、DOMAIN_MAX=(1,1,1)；离线生成定义见下文。文件头均声明 Cineon Log 输入、D65 白点和 DCI-P3 Gamma 2.6 显示输出。逐帧选择 Kodak 2383（默认）或 Fujifilm 3513DI，预览、缩略图、中性点吸管和导出共享该选择；切换只替换 D3 后的 LUT。原资产字节不变，哈希见资产清单。

工程默认：输入在 LUT 边界逐通道 clamp 到 [0,1]，记录域外计数；采用显式三线性插值，CPU 和 Metal 采用相同算法。`.cube` 红索引变化最快，行索引 `r + N*g + N*N*b`。坐标为 `u*(N-1)`，上界索引不得越界。GPU手动读取 8 个格点插值，避免硬件采样半像素坐标与精度差异。暂不提供四面体插值。

Final 按现有 P3-D65 Gamma 2.6 ICC 解释。LUT 后不再套 Gamma 2.6 编码。文件头语义作为实现依据；其色度正确性与完整视觉效果仍待实际验证，不能从文件名推断已经验证。

## 9. 预览、导出与中间阶段诊断

Metal与CPU内部保留Float32。仅显示副本量化为不透明UInt16 RGBA CGImage，Final携带固定P3-D65 Gamma 2.6 ICC，由macOS完成显示器适配；不重复Gamma编码，不把该profile替换成系统Display P3标签。显示副本不参与后续取样或导出。

未校准原图代理的显示副本标记为P3-D65 Linear（CoreGraphics extendedLinearDisplayP3），仅由显示系统执行显示器转换；原始样本和输入代理数值保持，禁止将L0当sRGB编码诊断图或LUT输出。显示副本仍采用16-bit SDR量化，展示身份为sdr-uint16-v2-original-linear-p3。

L0/L1/L2与D0–D3诊断显示各自的clamp(value,0,1)，作为sRGB编码伪色展示；诊断显示不修改内部值。主预览长边1600，RAW采样的代理语义见下文。展示策略独立版本化并参与缓存身份。

输出转换见§11；默认Display P3、16-bit TIFF、ZIP压缩。全部输出嵌入目标ICC、无alpha、无抖动、orientation=1。转换后检查有限值，16-bit量化为`floor(clamp(value,0,1)*65535 + 0.5)`；整数归一化使用65535，与密度的1024不同。

TIFF使用classic格式，支持无压缩及独立条带zlib Deflate。原始行块上限约2MiB、最多32行；超过classic TIFF的4GiB限制明确拒绝。完整写入临时文件后再原子发布，覆盖冲突和原片保护见architecture.md；JPG量化见下文。

## 10. 用户方向与原始坐标

用户方向是独立、帧级的 D4 整数变换，不改变以上公式。顺序为：读取 TIFF 存储样本 → 校正原始 TIFF orientation → 得到规范原始像素坐标 → 执行逐点密度/LUT 管线 → 用户追加方向。逐点运算与整数排列可交换，导出为减少临时内存使用反向坐标读取，结果必须相同。

帧方向用八状态 `FrameOrientation` 表示，操作按点击时间顺序在当前显示坐标系左复合；当前画面的水平/垂直翻转不能退化为总在扫描仪原坐标轴翻转。重置回 identity，只移除用户方向，不撤销 TIFF 元数据本身的方向校正。

取样点先由完整图像显示矩形反映射到用户方向后的全尺寸坐标，再经 D4 逆映射到 TIFF 已校正的原始像素。ROI 采用整数半开边界，完整反映射后保存原始坐标；缩放、平移和用户方向不改变采样数值。奇数次 90° 旋转交换导出宽高；输出实际排列像素，并写 TIFF orientation=1。

## 11. 输出转换与编码

菜单提供 sRGB IEC61966-2.1、Display P3（新卷默认）、Adobe RGB (1998)、ProPhoto RGB、Rec. 2020。旧 P3-D65 Gamma 2.6 已从输出枚举移除；原始 `ICC/DCIP3_D65.icc` 仅作为 LUT 的内部源解释保留。五份菜单输出固定 profile 独立打包于 `Sources/PrintroomCore/Resources/OutputProfiles`，来源与字节哈希见该目录 `PROVENANCE.txt`。不修改原始 ICC 目录。

Final 数值已经 Gamma 2.6 编码。全部五种输出解析固定 ICC 的 matrix/TRC，按源 TRC 解码 → D50 PCS colorants 矩阵 → 目标 TRC 反函数执行相对色度转换，黑点补偿关闭；Double 矩阵与曲线表插值计算后回到 Float32，最终量化一次。TRC 快速路径按 Double 指数／尾数每二进制倍频程4096段、覆盖 [2^-32,2) 进行线性插值；相同RGB曲线共享只读表，参数曲线断点所在区间、零、负值及域外值使用原解析实现，不提前裁切。源为原始 P3 profile，目标为真实选定 profile。ProPhoto 为 D50，TRC 编码域 E≥1/32 时解码为 E^1.8，否则为 E/16；D50 色适应已经包含在 ICC colorants 中，不能重复套 chad。

Display P3 使用 D65 白点和 sRGB 分段曲线，不等于原生 P3 Gamma 2.6。Rec. 2020 使用 BT.2020 原色、D65 白点和 Gamma 2.4 的 SDR 显示参照编码，采用本机 Adobe UHD_Display.icc；实际按固定 ICC 的定点参数计算，不使用相机 OETF 或 PQ/HLG。输出转换策略为 `printroom-output-icc-v3`；密度/LUT 算法 v6 不变。名称按用户截图对齐，不宣称与 Adobe ICC 字节或导出像素一致。

本机 ColorSync Float32 CMM 与 CoreGraphics 的暗部纯 Gamma 处理实测偏离 ICC 解析值，故不用于生产输出 CMM：P3 中性 0.02 → ProPhoto 应约 0.000612，而系统路径返回约 0.02。系统 ROMM profile 的参数断点也不合标准编码域；新增 ProPhoto profile 按标准生成。上述理由及精确来源见 `Sources/PrintroomCore/Resources/OutputProfiles/PROVENANCE.txt`，测试以独立矩阵/标准 TRC 解析值为主，正常域额外比较系统参考。

转换后按 §9 量化。TIFF 输出 3×16-bit RGB、嵌入目标 ICC、无 alpha、无抖动、orientation=1。支持无压缩（TIFF tag 259=1）与 zlib 包装的 Deflate（259=8），每块独立无损压缩；生产编码采用内置 libdeflate 1.24 等级 1，每次 writer 复用独立压缩器及输出缓冲，直接读取量化后的 UInt16 字节。每块最多32行，原始字节预算约2 MiB（超宽单行除外）。不使用水平预测器，解压样本、ICC、方向与条带结构契约保持，压缩后文件字节不要求一致。单张和批量共享 `ExportEngine`、`OutputColorConverter` 与 TIFF writer。

<a id="12-020-直方图"></a>

## 12. 直方图

统计 `PixelBuffer` 的整张照片，默认长边 1600 的最近邻预览，不是显示器截图、可见区域。Final 使用 ICC 显示转换前的 P3-D65 Gamma 2.6 编码值；L0/L1 使用线性透射率，D0–D3 内部使用归一化密度 N，横轴显示CV（见下文）。

每通道 256 bins，区间 [0,1]，索引 `min(255, floor(value*256))`。有限 <0 / >1 值单独计数，不塞进端点 bin；NaN/Inf 单独计数，不入 bins。恰为 0 或 1 的值既属于端点 bin，也单独计数。≤0 / ≥1 百分比以实际统计样本数作每通道分母，表示当前统计域黑白端边界；不意味着对中间密度执行裁切。所有统计只读、不修改算法值。

RGB 叠加与单通道共享同一统计结果。大于 131,072 像素的预览按原预览坐标的 4×4 网格取样，每格取 (起点+2) 并在末格夹到图像边界；小图保留逐像素统计。覆盖整张裁后预览，256 bins 与数值域保持。pixelCount 是完整预览像素数，sampleCount 是实际统计数；所有计数只指样本，百分比以 sampleCount 为分母，统计为取样估计，可能漏掉细小尖峰和稀少极值。完整 compute 接口保留精确统计。画面与统计由同一个渲染请求后台准备，在一次无挂起的主线程更新中一起发布；同上下文允许递增完成快照，跨帧/阶段/校准/几何旧结果丢弃。缩放和平移不替换整图统计。此近似仅用于直方图，不改变画面、取样吸管或导出像素。


纵轴仅用于显示：将当前可见通道的所有非零 bin 计数合并、排序，以 nearest-rank P90 × 4 为候选上限；下限为 max(1, sampleCount × 0.002)，最终上限不超过实际最高 bin。绘图高度为 min(1, count / 上限)，保持未截顶部分的线性比例。RGB叠加共用尺度，单通道按自身分布计算；空分布上限为1，稀疏/纯色分布可自然退回最高峰。零bin不参与分位数，端点和其他位置的峰同等处理。阈值为工程默认，避免单个大峰压扁主体，同时限制稀少样本被过度放大。仅改变显示高度，统计、像素、算法版本和项目schema均保持；不声称复刻Lightroom内部实现。

显示单位：D0–D3 的横轴以 `CV = N × 1024` 标示为 0…1024 CV，参考线位于 N=95/1024、470/1024、685/1024。只转换坐标标签，256 bins、归一化值和域外计数规则保持。

直方图选择独立于照片预览：Density取D3，Final取Final，默认Final，固定RGB叠加。使用同一输入、裁剪、方向和参数快照；详情弹窗已移除。


## 13. 算法版本与兼容

当前算法为`printroom-density-v6`，反差pivot为685 CV，运行阶段不增加LUT白点偏移。旧版470 CV pivot、运行时白点处理及Neutral选择的兼容由项目加载处理；旧参数不自动重新配光，首次覆盖前保留原项目备份。迁移与保存规则见[architecture.md](architecture.md#旧项目兼容)。


<a id="14-031-裁剪与精细旋转"></a>

## 14. 裁剪与精细旋转

裁剪是帧级、可恢复的几何编辑。当前 `FrameCrop.geometryVersion=2` 独立于密度算法版本；密度公式、685 CV pivot、矩阵、片基校准与 ICC 约定不变。未裁剪的帧使用 `crop=null`，保持原有预览与输出样本。

几何版本 2 的坐标基准是 TIFF orientation 校正后的原片，位于用户 D4 方向之前。几何顺序为原片 → 围绕原片完整画幅中心的细旋转与水平裁剪框 → 用户 D4 方向。FrameCrop 保存原片基准下的比例、横竖、规范化中心与宽度，宽度以完整原片宽度归一化，裁框高度由比例决定。正角在左上原点、y 向下坐标中表示顺时针；范围 ±10°，持久化到 0.01°。比例选择与锁定交互见interaction.md；原始与自定比例复用freeRatio存储，自由比例几何规则见下文；重置对应完整原图，不强制套用某个比例。

原片裁后宽高为比例整数分量的相同整数倍，例如 7k×6k；尺寸向内取整。零角裁框边界落在整数像素边界，保留样本；非零角按逆旋转后四角的有效范围自动限制尺寸，并约束中心使整框在原片内。移动裁框保留尺寸，改变比例、角度或大小时才可能收缩。后续 D4 方向操作保留存储的原片裁剪值，最终 90° 输出交换宽高。

界面把原片裁剪转换为当前显示方向的临时几何：反射使显示角度反号，90°交换显示横竖及宽度归一化基准。编辑显示值后转换回原片坐标保存。同步捕获同一原片裁剪，在各目标 TIFF 方向校正后的原始尺寸内适配；目标用户 D4 不参与拟合。同尺寸照片保存相同裁剪值，输出等价于先裁同一原片区域、再分别执行每帧 D4。

几何版本 1 是 0.3.0 的旧约定，坐标顺序为原片 → 用户 D4 → 细旋转与裁剪。读取时以该帧原始尺寸和既有方向转换为版本 2，保持既有画面；缺失或不可读原片保留版本 1，不能猜测尺寸。版本 1 也可作为界面的临时显示表示，提交前必须转换为版本 2。项目迁移、备份和兼容性规则见 [architecture.md](architecture.md#旧项目兼容)。

`CropGeometry` 为 CPU、Metal 调色入口、预览和导出共用的几何契约。以像素中心 i+0.5 映射回原始样本，非整数位置使用 Float32 双线性插值，然后才执行 L0→L1→L2→D0→D1→D2→D3→Final。D4 只排列像素，可与逐点调色交换，但不能改变原片裁剪的范围或角度。此处仅插值原始线性样本，不做输入 ICC 转换或 Gamma 解码，不在密度域插值。极外侧半个像素支撑使用边缘样本延拓；裁剪区域本身不得含空白。全尺寸导出从 UInt16 原图按最终几何一次生成有界行块，再走原有 ICC 与统一量化。连续修改角度不会累计重采样损失。

普通主预览与缩略图从有界全图低分辨率输入生成裁后画面；裁剪编辑时显示方向后的完整图像并旋转展示副本，用于构图，完成后使用上述线性采样路径重新出图。裁剪模式不显示直方图；普通直方图统计完整的裁后低分辨率画面，平移和缩放不改变统计范围。主画面的所有缩放共用1600代理，不读取原始区域或叠加细节图。TIFF的原始ROI仍用于片基/CMOS采样，单次采样上限8,388,608像素；导出保持原始分辨率。

片基取样模式临时显示完整原图及用户 D4 方向，不应用裁剪和细旋转，以便仍可选择片基边缘；保存的校准始终引用原始坐标。取样结束按裁剪预览开关恢复显示。普通点击不读数；中性点吸管的原片坐标取样见 §15。

<a id="15-033-final-中性点吸管"></a>

## 15. Final 中性点吸管

**用户确认**：以 LUT 后 Final 中性为目标，尽量保持取样位置的最终亮度，仅自动调整 RGB Timing。Master Timing、全部 Contrast、片基/矩阵、裁剪与方向不变。无论当前查看哪个诊断阶段，吸管目标均为 Final；不会自动切换所选阶段。

**用户确认**：中性点采样方形边长为未裁原片长边的 0.8%，不随源分辨率、裁剪或窗口缩放改变相对大小。采样版本 `neutral-relative-008-v1`。点击先按裁剪/方向逆映射至方向校正后的原片坐标，再按 `floor(sourceCoordinate × previewDimension / sourceDimension)` 映射到未调色、长边最多1600的最近邻预览网格；TIFF 与 RAW 共用此路径，RAW不重新解码全尺寸。网格边长为 `max(1, round(max(Pw,Ph) × 0.008))`，长边1600时取13×13（理想12.8取整），小于1600的源不放大。以选中网格像素为中心，偶数边长向负方向多一格，边缘仅截短，不移动窗口或重复边缘像素。

原始 RGB 须有限且在 [0,1]；任一通道为 0 或 1 的整个采样点排除，有效点必须严格超过邻域一半。核心求解限制最多169个点；无效/多数剪切时整次失败。仅新点击采用此采样版本，已存Timing不重算；密度算法、项目schema不变。

对每组候选 Timing，把所有有效样本经过完整既有管线到 Final，再逐通道求中位数（偶数取中央两值平均），得到代表色 `m`。不能把 D3 的中位数先送 LUT 来替代这项统计，因为三维非线性变换与逐通道中位数不能一般交换。

工作 ICC 沿用 §11 的原始、SHA 固定的 P3 profile。仅在求解器测量中解码 TRC，计算 D50 PCS XYZ；输出/显示仍使用原有 LUT 编码值，不重复 Gamma，不在密度域执行 ICC。定义：

```text
m[c] = median(Final[p,c])
XYZ(m) = ICC.colorants × ICC.TRC.decode(m)
W = ICC.colorants × (1,1,1)
y = XYZ(m).Y / W.Y
targetRGB = (ICC.TRC.encode(y), 同左, 同左)
```

该固定 ICC 三通道具有相同纯 Gamma TRC，故 targetRGB 三通道相等。亮度约束取点击前代表色的线性 Y，不使用编码 RGB 平均或 D3 平均密度。各候选代表色通过标准 CIELAB 分段函数、以 W 为参考白点计算 Lab，目标为原 L*、a*=b*=0。色适应已包含在 ICC colorants 中，不再叠加 chad。

**求解策略（工程默认）**：先缓存每个有效样本的 D3，候选整数前的连续变量为各通道 D3 CV 偏移；其与 Timing 的关系是 `deltaD3CV[c] = finalContrast[c] × deltaTiming[c]`。在 Timing ±512 所对应的有界区间内执行阻尼最小二乘，以 0.5 CV 有界中心差分估计 Jacobian。最多三个确定性起点：最接近目标编码 RGB 的 LUT 格点相对 D3 中位数的偏移、当前参数、D3 中性近似；每起点最多 48 轮，单轮最多 8 次阻尼尝试，单步最大通道移动 128 D3 CV。LUT 格点仅作为起点，不宣称构造完整逆 LUT或保证全局解。

连续解转回 Timing 后，在各通道四舍五入值 ±2 的整数组合中，用真实 Float32 完整管线重新求 Final 代表色。越出 ±512 的候选不应用；通过下列质量门槛的组合按 Lab 到目标的平方距离择优，数值同分优先较小 Timing 移动：

- 中性色差 `C*ab = sqrt(a*²+b*²) ≤ 1.0`。
- 亮度变化 `abs(L*after − L*before) ≤ 0.5`。

以上是吸管工程容差，不代表硬件色度验收或所有像素严格 RGB 相等。原代表色已在中性容差内则参数原样返回，使重复点击不会漂移。整数精度、范围边界、LUT 剪切/平坦区或无法收敛可能导致无合格解；求解器仍抛出失败，界面按 interaction.md 静默结束，并保留全部原参数。不会把一个超差近似值当作成功标定。只保证所选邻域代表色，不能保证整条灰阶或全图中性。

求解在可取消后台任务中运行，提交前再次校验帧/卷、调色、校准、几何、阶段、原始尺寸、LUT/ICC、修订、取消令牌与源文件指纹。成功作为已有单帧事务一次撤销；失败和取消不增加撤销或保存。

此功能仅产生既有整数RGB Timing参数；旧项目不自动重算，使用吸管时才提交新的调色结果。


<a id="16-035-cmos-标定与双矩阵"></a>

## 16. CMOS 标定与双矩阵

**用户确认**：L0→CMOS→L1→Gain→L2→D0→密度矩阵→D1；矩阵均为卷级。矩阵应用自动联动片基对齐，具体规则以§6为准。CMOS制作支持三张TIFF／RAW或混合选择；RAW使用代理代表值。借鉴 LightSourceDecouple 功能思路，不要求与其裁切/截断的中间 TIFF 逐像素相同。

CMOS 标定工程实现：三张分别仅开启R/G/B光源的照片。经SourceImageIO保持样本值读取，按 orientation 校正后的中心宽高各 20% 区域计算 Double RGB 算术均值（整数尺寸向下取整；尺寸≤10 的轴取全轴）。每个相机通道在三张图中的最大均值确定光源角色，必须一一对应。令均值列向量构成 `A=[vR vG vB]`，`B=inverse(A)`，`CMOS[i,j]=B[i,j]/sum_j(B[i,j])`。行归一化仅用于此 CMOS 求解，保持等值 RGB；结果转为 Float32，允许负系数。

工程失败条件：重复/不足三张、不可读/不支持的输入、区域内任一 65535 剪切样本、非有限或非法均值、角色重复、`||A||∞×||A⁻¹||∞ >= 1e8` 或非有限、`abs(rowSum) <= 1e-8×sum(abs(row))`、Float32 非有限系数、读取期间源大小/mtime 改变。失败不覆盖已保存矩阵，也不改变卷设置。标定计算在后台，可取消。

内部 L1/L2 保留 Float32，不裁切、不量化、不做 ICC/transfer 转换。有限负值进入密度时仍按 §4 的 epsilon 处理；非有限中间值在 CPU/Metal 均失败，不允许被 LUT 裁切隐藏。

导出统一为Final，按 §11 执行 ICC 转换与量化。CMOS 校正仍为管线内部 L0→L1 阶段。


## RAW 输入契约

RAW 策略独立版本为 `adobe-linear-camera-rgb-v1`。输入开放常见品牌 RAW 和 DNG，扩展名由 SourceImageIO.rawFileExtensions 统一定义，格式列表见 [使用指南](user-guide.md#raw-格式)；开放扩展名不等于每个机型或压缩模式均已验收。真实验收范围仍为 Sony ILCE-7CM2 的八张样片。仅 Adobe DNG Converter 执行去马赛克：单遍参数 `-u -l -p0 -dng1.1`，禁止加入 `-cr5.4`，转换失败不能改用其他去马赛克后端。所有 RAW（含输入 DNG）均通过该流程准备；具体机型须由本机转换器支持，并通过后续读取验证。读取真正主图并验证 uncompressed UInt16、三通道、LinearRaw (34892)、无 CFA filters；DNGVersion 不必等于 BackwardVersion。此次开放格式不修改转换参数、算法版本、代理版本或旧项目数值。

静态构建 LibRaw 0.22.1 执行 `open_file → adjust_to_raw_inset_crop(3,0) → unpack → dcraw_process → copy_mem_image`。固定 `user_mul=[1,1,1,1]`、`output_color=0`、`user_flip=0`、`highlight=1`、`output_bps=16`、`no_auto_bright=1`、`user_qual=3`、`gamm=[1,1]`、`adjust_maximum_thr=0`、`use_camera_matrix=0`。不再做黑位归一化、相机白平衡、自动亮度、ICC 转换或 Gamma。有效裁剪/黑位来自实际 DNG 和 LibRaw，不硬编码机型尺寸。

所得 UInt16 线性相机 RGB 进入现有 L0 输入；原 TIFF 样本读取行为不变。内部 TIFF 无需嵌入相机色域 ICC。`user_flip=0` 保留参考样本布局，RAW 源 EXIF 方向不自动旋转 RGB；用户方向和原片裁剪仍按现有几何契约应用一次。

`nearest-original-1600-v1` 代理按长边 1600、尺寸向下取整，由完整有效图逐像素 nearest-original-sample 取样；240 缩略源独立从完整图取样，不能从1600代理二次取样。两者均保存未调色的 UInt16 TIFF。首次代理仍需全尺寸 Adobe 和 LibRaw 处理，但不先写完整 TIFF。日常 ROI/片基/中性点/CMOS 制作仅使用代理；导出才重新调用 Adobe 并解码全尺寸，直接交给导出器，不落 full.tiff。DNG 仅在本次准备/导出临时目录存在，用完删除。

三张标定图允许 TIFF、受支持的 RAW 或混合选择。RAW 使用既有 SourceImageIO 线性转换，原片中心 ROI 映射到代理参与标定；读取冻结 RAW 处理身份并检查源文件变化。求解、曝光拒绝和中性归一化沿用 §16。Sony A7C II 内置系数直接来自用户 NPY，仅转换为管线 Float32，不转置、不再次归一化；阶段顺序与算法版本不变。

## BigTIFF 输入

TIFF 输入同时支持版本 42（classic）与 43（BigTIFF）；BigTIFF 使用 8 字节偏移、8 字节目录项数量、20 字节目录项与 8 字节内联值，条带地址和字节数支持 LONG8。样本约束沿用 §2：chunky RGB UInt16、无 alpha、单页条带、无压缩（259=1）、LZW（259=5）或 Deflate（259=8/32946）、水平预测和八种 orientation。不支持 tiled 或其他位深。LZW 按 TIFF 6.0 使用 MSB-first、9–12 bit early-change 码、条带独立字典及 Clear/EOI；解压长度必须等于条带原始样本字节数，先解压再恢复水平预测。ICC 仅作为元数据，解码数值、算法版本和项目 schema 不变。输入不再以 4 GiB 限制样本总量；维度与乘法先校验可寻址范围，读取前校验文件边界。预览和 ROI 按所需条带读取，完整图像和单个条带仍需要相应内存。输出继续使用 classic TIFF 及既有 4 GiB 拒绝行为。


## RAW 日常代理采样

用户确认日常完全走代理、全尺寸仅用于实际导出。TIFF保持原始样本读取。编辑采样版本 `proxy-region-nearest-v1`：原片整数坐标 `(x,y)` 映射到1600代理的 `(floor(x*Pw/W), floor(y*Ph/H))`；ROI 返回原坐标网格尺寸，值取对应代理像素，不宣称包含原片精细信息。片基逐通道中位数、CMOS中心均值使用此网格（中性点取样使用§15的独立预览网格范围）；因此可能多次取到同一代理像素，代表值相较全尺寸取样可能不同。保存的选区/尺寸/裁剪仍为原片坐标，旋转和裁剪导出范围不变。手势缩放始终放大同一代理预览。

1600/240原代理生成规则和 RAW 处理身份保持；其他预览尺寸从1600代理缩小，不为放大请求重新解码。首次代理制作仍需全尺寸 Adobe/LibRaw 临时处理。Final导出从原片重新转换，沿原有完整分辨率和算法执行，不以代理补偿或替代输出；失败不得回退代理。旧项目已存校准和矩阵不自动重算，只有新取样/相关矩阵重采样采用本节规则。

## 简易 Timing 坐标

简易 Timing 只生成 §7 已有整数参数，不增加管线阶段。设有效用户偏移 `r=master+red`、`g=master+green`、`b=master+blue`（不含片基偏移）：

```text
E = (r+g+b)/3
T = (r-b)/2
H = (r+b-2g)/6
r = E+T+H
g = E-2H
b = E-T+H
```

E/T/H 分别显示曝光、色温、色调，均为相对 CV 坐标；不标 EV 或 Kelvin。工程默认每个轴单步为1，对应有效偏移向量 `(1,1,1)`、`(1,0,-1)`、`(1,-2,1)`。正向对应当前2383中间调更亮、更暖、更洋红；不保证非线性LUT及非单位RGB反差之后亮度/色相严格独立。

切换模式只反解显示，不写入或舍入原参数。已有RGB可能反解出分数，界面显示四舍五入后的整数，底层保留分数；编辑将目标与当前轴值的差四舍五入为整数步数，保留其他两轴。因此从旧RGB继承的分数余量保持，输入0/双击复位达到当前整数格点上最接近0的可达值，误差最多半步（若受范围约束则停在边界）。普通简易模式从全零开始没有分数余量。

各控件仍须满足 §7 的独立±512。沿整条轴限制移动，使有效RGB各自位于±1024且最大与最小之差≤1024，禁止分别截断通道。对移动后的有效RGB，合法Master区间为 `[max(-512,maxRGB-512), min(512,minRGB+512)]`；曝光优先让Master随轴移动，色温/色调优先保留Master，必要时在合法区间内重分配Master/RGB，合成偏移精确不变。显示全域E±1024、T±512、H±1024/3，实际可达区间受另外两轴约束。

现有CPU/Metal共享已生成的Timing参数，已存照片不自动修改。

## LUT 漫反射白直接烘焙

采用离线烘焙表。当前资源使用 `assets/DerivedLUTs/diffuse-white-v1/` 的两份65³表；原始LUT目录字节不变。仍为 `Final=F_baked(clamp(D3,0,1))`，不新增运行时步骤、偏移字段或输出增益。密度公式、矩阵、片基、Timing、685 CV反差pivot保持。

离线生成以p=(685,685,685)/1024为Cineon漫反射白，使用原表F(p)经固定P3 ICC解码后的线性Y，生成相同Y的等值RGB目标t。求固定RGB输入平移s，使最终65³表的三线性插值在p处等于t；每个格点q写入F(clamp(q+s,0,1))。直接对最终表在p周围八个格点求解，包含9位小数存储回读验证。生成脚本为scripts/generate-white-luts.py，系数、目标、源/输出SHA及重采样误差记录在派生manifest。

此方法只对齐参考白，不强制全灰阶中性，也不把漫反射白提到输出1。均匀格点重采样与连续输入平移存在误差，尤其在LUT陡峭区域；不宣称等同历史v4像素。当前算法身份v6区分图像与缓存。

## 自由比例与整卷自动裁切

自由比例沿用原片几何版本2与上述旋转/采样顺序，`aspect=free`、`freeRatio`保存横竖切换前的连续宽高比；实际比例仍按portrait决定是否取倒数。自由裁框宽、高分别向内取整为整数像素，并回存实际整数比例，重复拟合和D4转换不累积缩小。固定比例的整数倍取整规则保持。自由边把手只改变对应维度，角把手可独立改变两个维度；切换到自由时保留当前矩形。未裁照片初次进入裁剪使用完整原图比例（几何以freeRatio保存，界面默认锁定）；锁定不改变整数像素拟合规则。

自动检测版本`roll-edge-v6`使整卷尺寸识别和逐帧定位共用片基支持的边界评分，不依赖片基选区、矩阵、Timing、Contrast或LUT；不把漏光本身作为失败条件，不自动去除漏光画面。每卷固定一个以原片像素计的画幅宽高，只拟合逐帧中心与小角度，不分组；允许扫描边框与完整文件尺寸不同，适用于有效画幅像素尺寸一致的照片。输入为未裁切线性代理（RAW不额外请求全尺寸），按面积平均到宽800及等比例取整高度，再逐像素计算RGB平均自然负对数（样本下限1/65535），sigma0.65高斯平滑。

每帧seed同时保留方向校正后的原片宽高W/H。卷内以原片宽度最大、同宽时高度最大的照片作为参考，其分析尺寸为aw/ah、原片尺寸为Wref/Href；比较尺寸时把每帧横向边位置乘以`(W/analysisWidth)*(aw/Wref)`，纵向乘以`(H/analysisHeight)*(ah/Href)`。候选权重、片基参考与角度不改；只统一距离单位，不重新采样密度。整卷三角窗仍为参考分析网格3像素，模板保留参考原片尺寸。第二遍把模板横向尺寸乘以`(Wref/aw)*(analysisWidth/W)`、纵向乘以`(Href/ah)*(analysisHeight/H)`后在各帧自己的分析图上定位；由此固定的是有效画幅原片像素数，而不是扫描总宽高的比例。各帧第一遍与第二遍的原片尺寸须一致。历史无原片元数据的测试路径保留原分析网格单位，不用于应用入口。

四边搜索带分别为图宽2.5–18%、82–99%，图高1.5–14%、86–99.5%；初始角度±3°，先以0.3°粗搜，再将得分最高的三个粗角度各自±0.2°邻域按原0.1°网格细搜（重叠角度只计算一次）；最终同分选较小角度。边位置始终保持完整搜索带和0.5分析像素步长。纵边沿图高中心±38%取170点，横边沿图宽中心±37%取240点；内外2px密度差除0.22、内外0.6px密度差除0.9，分别夹到[0,1]后以0.55/0.45组合并平均。此分数是边缘支持度，不是正确概率。

初始角度目标仍为最强三边之和+0.4×最弱边，原始seed边位置和角度继续用于第二遍定位。在该角度下，每侧从原搜索带的局部极大值（含端点、平台）中按支持度降序保留最多8个候选，支持度至少0.08、间距至少3分析像素；同分按位置顺序确定。

候选的片基判断同时用于尺寸估计和逐帧fit目标，检查仍使用原始边缘支持度和原阈值。在原沿边范围内，纵边85点、横边120点，每点向内/外各取距边4、6、8分析像素的密度。候选片基密度为全部外侧样本中位数；外侧稳定性S为每个沿边点三个外侧样本极差的中位数；持续向内密度上升B为逐点`clamp((median(inner)-median(outer))/0.22,0,1)`的平均。初始权重`q=edgeSupport*exp(-S/0.2)*B`，避免窄夹具条纹因局部梯度强而占优。

每帧以所有候选外侧密度作为片基候选值b，计算四侧各自最大`q*exp(-abs(baseDensity-b)/0.25)`之和，取最大和对应的b；每侧最多一票，避免多纹理侧垄断估计。每个候选最终权重再乘`exp(-abs(baseDensity-b)/0.25)`。本机曝光差异可改变各帧的b，无需人工片基校准，不读取用户校准参数。b与候选一起保存在本次分析的seed中供第二遍复用；定位时不重新估计b，避免移动裁框改变片基参考。

尺寸配对仍要求两侧最终权重均>0.03，配对权重为`sqrt(q1*q2)`。没有可信边缘时的历史尺寸建议采用四边支持度均>0.3的帧尺寸中位数；不足5帧则使用原初始总分最高的最多18帧，再内接到指定比例，仅作为待检查回退。

正式自动裁切必须传入用户指定的原片宽高比r（有限正数，范围0.1～10），不再自动决定比例。预处理和边界搜索沿用本节约定；模板宽高改为一个尺度变量。分析网格高度取整时，使用参考照片的 `rGrid=r*(aw/ah)/(Wref/Href)` 补偿，不将代理或分析高度的取整误差引入原片比例。

沿用片基支持候选配对及权重，所有横向配对尺寸除以rGrid、纵向配对尺寸直接作为高度候选t；排除超出图像尺寸的候选。对每帧分别取横、纵配对的最大三角窗支持X/Y（窗口仍为3分析像素），总分为整卷 `sum(X+Y+min(X,Y))`；按高度升序遍历，同分保留较小尺度。获胜模板为 `(t*rGrid,t)`，比例约束同时参与尺度选择而非检测完再裁成目标比例。某一轴无可信边缘时可由另一轴推导；两轴均无可用候选时，仅将历史尺寸建议内接到指定比例作为待检查建议，不自动更改比例。历史无比例模板路径保留用于回归基线及无边缘尺度回退，不作为应用入口。

定位、内收和检查沿用本节约定，保存用户指定比例，经既有整数几何约束允许像素取整误差。每卷一个比例，不自动区分混合画幅或扫描分辨率；选错比例或画面边缘超出既有搜索带时仍需人工检查。某张完整扫描不足以容纳模板时，按横纵可容纳范围的较小缩放系数等比内接，并强制标记待检查，不缩小其他照片的模板。检测版本v6；重新运行才改变裁框，不迁移已有裁剪。

第二遍固定整卷宽高。每个轴分别用权重>0.03的低/高侧候选加/减半尺寸生成中心，按两侧各自最大的`weight*max(0,1-abs(candidatePosition-predictedEdge)/3)`之和排序，保留最多2个相距至少1.5分析像素的中心；同分按中心坐标排序。某轴无可信候选时使用原始seed两边中点。候选中心先排除不可能容纳该轴尺寸的位置。横纵中心组合生成最多4个起点，初始角度沿用seed；旋转后矩形须完整位于原图内，所有起点无效时回退原图中心、零角度。每个起点进行最多180次Nelder–Mead细化；移动和旋转过程中重新测量边界，调用与尺寸候选相同的片基支持评分、固定使用该帧第一遍的b，目标仍为最强三边之和+0.55×最弱边。细化过程中同样拒绝越出原图的矩形，避免越界最优解在最终几何约束时被平移成未经评分的位置。尺寸识别、定位起点和定位评分均不读取用户已保存裁框。

两阶段间仅缓存待拟合帧的800宽平滑密度图，总像素缓冲预算128 MiB（不包含当前代理、临时分析缓冲与少量seed/元数据）；按卷顺序填充，拟合一张后释放一张。超出预算的帧仍携带第一遍seed重新读取代理并生成密度图，所有来源修订检查、取消及最终整卷复查保持。缓存不写原片或用户项目，不改变导入机制。

最终裁框的待检查判定保持原口径：卷内原顺序的第一张和最后一张必须四边均>0.22，其他照片至少三边>0.22；全部照片还须四边均值>0.34且检测角度绝对值<3°才自动通过。缺失照片不参与顺序。未通过仍应用建议框并标记待检查，首尾规则只改变检查分流，不改变检测框。

检测框角度与裁剪校正角度相反；转换到原片规范化坐标，以自由比例保存，经既有约束与0.01°精度处理。用户设置的每边内收百分比 `p` 限定为0–5，检测结束后令宽、高分别乘以`1-2p/100`，中心、角度和自由比例不变；内收不参与边缘支持度或通过判定，每次运行从本次检测框计算，不累计。图像算法仍为`printroom-density-v6`；新增crop选择会改变几何，旧照片不自动运行检测。

## 悬停直方图取样

仅用于观察，不修改照片。中心按当前裁剪/方向逆映射回原片，沿用§15的未裁原片长边0.8%方形预览网格、取整和边缘截短规则；TIFF/RAW使用已加载未调色预览，不进行磁盘或全尺寸读取。每个邻域像素按已显示直方图对应的校准、调色和LUT处理到所选阶段，再逐通道取中位数（偶数取中间两值平均）。Density为D3归一化数值（横轴CV），Final为显示器转换前P3编码值。保留0/1剪切输入，不应用中性求解器的剪切排除或中性合格条件。CPU参考管线处理最多169点；非有限/处理错误隐藏标记。原片邻域可跨过裁剪边界，与吸管保持同一取样区域。不改变直方图统计、图像算法版本或项目schema。

## 整卷自动 Timing（roll-timing-v4）

用户确认：先沿用原算法求整卷唯一一组 RGB Timing，四项 Contrast=1；未启用自动曝光时 Master=0，启用时再独立计算每帧 Master；用户已完成裁切，必须先完成有效片基对齐。结果覆盖现有参数，不基于旧调色累加。运行管线仍为 density-v6，不改变项目结构。

统计范围（2026-10-10）：按项目帧顺序排除第一张和最后一张，再过滤缺失文件；首尾缺失不向内追加排除。至少三张且至少一张中间照片可用，否则整次分析失败。首尾像素不参与共同曝光和色偏求解，但仍接受整卷应用；第一张保存的LUT选择规则保持。未启用自动曝光时不读取首尾；启用时首尾仍参与各自Master计算，不进入整卷统计。仅重新分析并应用改变参数，旧调色、density-v6、schema和几何版本不变。

曝光规则（用户确认）：参与统计的每帧裁后均匀取样并等权汇总，以片基校准后、Timing=0/Contrast=1 的 `V=(R_CV+G_CV+B_CV)/3` 为曝光统计指标。按 nearest-rank 取整卷 P95，`E=685-P95`。V 是密度指标，不是物理亮度；不将分位数解释为实际90%反射率识别。685不是截断点，约5%的有效样本可超过它；是否最终剪切取决于LUT。

取样工程默认：每帧使用现有未调色1600代理，按实际原片尺寸、裁剪和方向经CropGeometry生成裁后预览。64×64分层网格取像素中心，排除任一原始代理通道非有限或不在开区间(0,1)的样本；至少64个有效网格点，再按稳定索引等距重采样为1024个样本，各帧严格等权。可能重复采到相同代理像素，不代表1024个独立原片像素。逐帧读入，整卷仅保留密度样本。有效点不足时整次分析失败，不默默丢弃该帧。缺失文件不参与，应用后状态报告跳过数量。

色偏工程默认：求`CR+CG+CB=0`，最终`T=(E+CR,E+CG,E+CB)`。全卷统一使用分析开始时项目帧顺序第一张照片保存的LUT求Final（首张缺失仍取其已保存选择；缺失照片不贡献样本），不取当前选中照片或第一张非缺失照片的LUT，以工作ICC真实TRC解码为线性RGB；逐帧加权平均，再逐通道对帧均值去掉两端各floor(帧数/10)个值，得到整卷稳健平均色。颜色权重固定由曝光调整后的基准输出计算：`w=0.05+0.95*clamp(meanLinearRGB/0.02,0,1)*clamp((1-meanLinearRGB)/0.15,0,1)`，候选不能通过改变权重隐藏颜色。整卷均值归一至平均线性RGB=0.18后，按工作ICC转Lab，最小化a²+b²；不是把每张照片拉成中性。

确定性坐标搜索沿三种零和通道差方向，步长64/32/16/8/4/2/1/0.5/0.25 CV，每档最多12轮。最终检查最优R/G邻近±2整数，并令`B=round(3E)-R-G`，全部通道限定±512。因此保存后的平均密度曝光误差最多约1/6 CV（另含浮点误差）。E超范围或无可行解报错，不逐通道强行截断。算法是局部数值优化，不保证任意LUT下的全局最优或真实场景白平衡；统计权重与观感仍需真实胶卷验收。

自动曝光（2026-09-29 用户确认）：可选第二遍，仅在整卷 RGB 求解完成后执行，不改变已求 RGB。复用每帧裁后密度样本，令 `V_i=mean(densityCV_i)+mean(savedRGBTiming)`，按 nearest-rank 取该帧 P95，`Master_i=clamp(round(685-P95_i),0,512)`，使用保存的整数 RGB 计算并保存整数 Master。只增加曝光，已到达白点的帧为0，所需增量超过范围时取512。此限制针对新增逐帧步骤，原整卷曝光锚点算法保持。P95仍是密度统计指标；夜景与低调画面可能被提亮，不承诺场景语义曝光判断。无需额外原片读取，缺失帧不生成结果；结果按帧UUID匹配，受保护帧不应用。不改运行density-v6或项目schema，仅重新分析并应用时生效。

## JPG 输出

8-bit JPG，与TIFF共享Final、裁剪、方向及§11的真实ICC转换；转换后检查有限值并按`floor(clamp(value,0,1)*255+0.5)`直接量化，无抖动、不经16-bit中转、不再次Gamma编码。ImageIO JPEG编码质量固定1.0（工程默认，仍为有损），附带所选RGB ICC、orientation=1；每边上限65500像素。TIFF的16-bit、压缩和数值规则保持。只扩展输出编码，不改变density-v6或既有预览。

## TIFF/RAW 统一预览代理（2026-10-01）

TIFF与RAW的编辑主预览和缩略源共用1600/240未调色UInt16磁盘代理及后续几何、密度、LUT、直方图和显示管线。代理网格沿用nearest-original-1600-v1：尺寸向下取整，像素位置floor(x*W/Pw)、floor(y*H/Ph)。两种尺寸独立从规范原图抽样；TIFF先校正输入orientation，再从原始UInt16样本抽样，不执行ICC转换或Gamma解码，不从1600代理二次生成240代理。压缩读取支持范围沿用TIFF输入契约。

## 齿孔置白（sprocket-whitening-v1）

用户确认：齿孔一定在每帧裁剪框外；设置为卷级，入口在自动裁剪左侧。此处理独立于density-v6，仅作用于Final。未启用、未校准、无有效裁框、片基采样或裁剪编辑期间保持原输出；不修改原始输入、密度、Timing、Contrast、LUT及几何参数。

工程默认：阈值25%，可调5–200%、步长1%。每像素用与片基相同CMOS矩阵处理后的线性RGB判断，全部通道都应比片基更亮，避免单通道亮色被误判。定义：

```text
relativeRGB = (CMOS × L0) × gainRGB / 0.75
brightness = min(relativeRGB.r, relativeRGB.g, relativeRGB.b)
threshold = 1 + thresholdPercent / 100
u = clamp((brightness - threshold) / 0.05, 0, 1)
alpha = u² × (3 - 2u)
```

0.05为五个百分点的亮度过渡宽度，不扩张空间蒙版。蒙版按CropGeometry把当前完整图像像素中心反映射至原片，再映射至该帧已保存裁剪的单位矩形，覆盖全部D4方向、非居中裁框与微调旋转。矩形内及四边均强制alpha=0，边界另加4e-6单位坐标的保守浮点保护范围；所有过渡限制在框外。

Final编码值按`Final + (1-Final)×alpha`合成，alpha=0直接保留原像素，alpha=1直接写(1,1,1)。CPU与Metal分别实现阈值和合成；GPU读原始线性缓冲，不把复用D1当成线性输入，卷级阈值不使D1缓存失效。L0–D3诊断和吸管求解不经过合成。

导出冻结卷级设置及每帧裁框。勾选应用裁剪时直接沿用原裁后输出；取消应用裁剪时，在原片完整画幅内按保存裁框保护画面，忽略输出微调旋转、保留D4，条带使用全图行偏移。白色合成先于ICC转换，以保持预览一致的边缘颜色；完全不透明的孔洞在转换后再固定为目标空间(1,1,1)，保证16-bit TIFF内部为65535、8-bit JPG编码输入为255，JPG回读允许有损误差。两种格式共用量化实现，未启用的输出数值不变。

主预览关闭裁剪预览即可看到完整底片上的效果，裁后预览、缩略图和直方图仍保留裁框内结果。亮度阈值及过渡为工程默认，真实胶卷的识别与边缘观感待人工验收；当前不使用齿孔形状识别，框外片外直射光也可能置白。
