# 架构与项目数据

当前契约：0.3.69。Swift Package 包含 Core、SwiftUI/AppKit 应用、LibRaw/CRawBridge、CLibDeflate 和测试；`scripts/build-app.sh` 生成固定 `output/Printroom.app`。公式仅见 [pipeline.md](pipeline.md)，用户交互仅见 [interaction.md](interaction.md)。历史过程与逐版验收由维护者在本地保留。

## 当前模块与所有权

| 模块 | 职责 |
| --- | --- |
| EditorModel / EditorView / PreviewCanvas | 会话、选择、命令、撤销、显示与草稿；异步结果发布前验证来源和修订 |
| ProjectPersistence | 持有延迟保存任务与最后成功保存令牌；失败不推进令牌；编辑器保留 dirty 和错误展示 |
| ProjectStore / RollProject | 发现、验证、版本解码、迁移备份、文件协调、原子保存、重连 |
| ParameterSnapshot / FrameRecord.applyManualCrop | 调色快照的全量/选择性覆盖及统一裁框约束；先完成值事务再提交整组撤销 |
| SourceImageIO / TIFFCodec / SourceProxyService | 原始样本读取边界；TIFF/RAW共用代理服务与按需全尺寸读取、同源复用、取消及跨进程锁 |
| SourceStamp / ImageService | 共用新鲜源属性与 RAW 处理身份；有界未调色缓存、区域读取、片基与中性点取样 |
| PreviewRenderService / PreviewPresentationCache | 主预览与缩略图通道的渲染与显示准备、几何/D1复用、有界显示占位缓存 |
| DiskThumbnailCache / ManagedDiskCache | 可再生 Final PNG 与统一磁盘预算；代理维护先清旧RAW中间文件，生产容量统计仅由统一管理器执行 |
| AutoCropService / AutoCropAnalyzer | 两阶段卷级分析、128 MiB目标密度图缓存、超限seed回退、逐帧拟合与全卷来源校验 |
| Pipeline / MetalPipeline | 独立 CPU 数值参考与遵循相同契约的 GPU 实现；不能为了消除重复而共用同一计算实现 |
| ExportEngine / TIFFCodec / JPEGCodec | 不可变导出快照、最多四路完整帧任务、真实 ICC 转换、编码与冲突发布 |

ImageService 不再提供旧全图读取、单像素或导出包装。全图读取使用 SourceImageIO，导出统一使用 ExportEngine。校准诊断仍在 Core，日常取样不再重复计算已移除的说明文字统计。Core 图像对象仍保留原始 ICC 诊断信息。

## 当前项目与保存

- `schemaVersion=9`、`algorithmVersion=printroom-density-v6`、`geometryVersion=2`。文档整理不改变版本或像素约定。
- `calibrationNeedsReview`仅保留旧JSON兼容解码/编码，打开或重连时清零；渲染、色罩分析和齿孔置白不再使用此字段限制行为。
- 每卷 `.printroom.json` 保存卷 ID、名称、资产身份、输入解释、片基及矩阵快照、有序帧数组、导出偏好和当前帧 ID；帧以 UUID 标识，文件名为卷内相对路径。多选、撤销、复制快照、渲染任务、缓存像素、裁剪比例锁定和裁剪预览开关不写入项目。
- 逐帧保存 Timing、Contrast、LUT、独立 D4 方向、原片坐标裁剪、裁剪来源/检查状态、缺失状态、源大小/mtime及可选 RAW 处理身份。卷级矩阵库快照不依赖本机库继续存在。
- 卷级`sprocketWhitening`保存独立策略版本、开关与阈值；缺失字段默认关闭。schema8及更早项目只读迁移到schema9，首次覆盖保留原字节备份，旧画面不自动改变。
- 导出偏好保存格式（沿用位深字段）、profile及哈希、压缩、应用裁剪、可选目的地和前缀。缺省前缀跟随卷名；取消设置窗口不提交。
- 调参防抖2秒，操作结束和批量命令立即保存。成功保存才更新修改时间令牌；冲突、失败保留 dirty、参数与撤销。切卷/主页/退出沿用保存检查。
- ProjectStore 在同一文件协调内核对修改令牌、项目ID及格式，旧格式首次覆盖前独占写入原字节备份，最后原子替换。损坏和未来版本禁止重置覆盖。
- schema1–8、旧算法、Neutral选择和geometry1的现有解码/备份继续保留。旧几何需要各帧真实尺寸，缺失源保留旧值等待恢复；不猜测、不自动丢弃旧调色。
- 设置副本仅允许恢复到同一卷。重连限定卷内直接子文件，保留稳定 ID 和编辑，目标已有编辑时禁止合并。片基作为独立数值快照继续使用，不因来源或处理身份变化进入复核；仅显式矩阵操作的重采样需要可读来源。

## 编辑与批量事务

单张裁剪提交只影响当前帧。批量裁剪统一由“同步…”读取已提交来源，排除当前帧，保留目标各自方向；不再保留旧的裁剪模式内批量入口。同步先验证全部目标并构建新项目值，全部成功才发布、注册一次撤销、更新缩略图和保存。复制/粘贴仍使用复制时的调色快照，而选择性同步使用点击时当前参数。

普通切帧时的草稿保存、自动裁剪检查确认、取消和重置保持各自语义。撤销恢复编辑参数并保持当前卷名及导出偏好；不把操作合并成与现行界面不同的撤销组。

## 渲染、输入与缓存

- 主预览使用一个在途请求和一个可覆盖待办，同上下文结果依次发布；切帧、来源、几何、矩阵等上下文变化取消旧任务并拒绝旧结果。已校准时主预览与直方图以匹配快照一起发布；未校准时主预览/缩略图仅呈现未处理代理，不发布直方图，显示缓存通过校准快照区分原图和处理画面。
- 显示裁剪与统计裁剪分离。关闭裁剪预览显示完整画面，直方图仍按保存裁剪统计；缩略图、分析和导出不读取这个开关。
- 显示缓存保存画面、源尺寸和匹配的直方图，统计按其阶段验证后恢复，统计数组计入字节预算；不缓存取样输入或悬停快照。切帧未命中时保留上一份显示快照与画布视口，停止旧手势及取样；缓存命中或目标正式结果发布时统一替换，异步工作仍校验来源和修订。暂留画面不用于目标帧裁剪或取样。
- 主预览和缩略图保留独立渲染通道与GPU缓冲，避免互相驱逐或排队。未调色主预览缓存默认1664MiB/40项，显示占位缓存832MiB/40项，均按实际使用分配并按LRU淘汰，可容纳40张长边1600的近方形照片及直方图。编辑器缩略源通道独立限额16MiB/12项。仅使用正式预览缓存，不放大240缩略图占位。原始采样区域上限8,388,608像素。缓存不能成为业务真相。
- 当前卷首张预览与缩略图任务就绪后，编辑器空闲1秒启动utility预加载：以当前主预览帧为中心按距离扩展，最多40张，一次只读／渲染一张，帧间暂停120ms。复用主预览输入缓存，使用独立临时GPU会话预备当前阶段／显示裁剪及直方图；只填缓存，不改变选择、项目或显示。切帧、调色、导出、分析、裁剪和取样取消预加载；已提交GPU命令仍须完成后丢弃过期结果。提交缓存前验证卷、帧、来源、校准、参数及显示快照，预加载失败不产生前台错误。卷切换／主页／导入取消旧任务，空闲后按新当前帧重新排序；不扫描其他卷，不保存完整正式显示到磁盘。
- SourceStamp 统一预览/分析的路径、size、mtime及RAW处理身份；TIFF仍比较inode，RAW不比较inode、设备号或ctime。RAW底层修订只含大小和纳秒精度mtime，旧项目七字段修订按相同规则比较。输入缓存、分析在途结果与导出继续校验各自来源，已存片基不复核。几何准备保留自身快照校验。
- TIFF/RAW通过SourceProxyService共用任务合并、跨进程源锁、四槽、代理校验/发布与维护；SourcePrewarmer准备整卷后才进入编辑，缓存命中复用、失败可重试。两种输入均生成独立1600/240未调色UInt16代理。RAW通过Adobe + 固定LibRaw生成，DNG用完删除，导出重新解码全尺寸；TIFF从原片分别抽样两个网格，片基/CMOS采样与导出保留原始读取。缓存契约和网格见pipeline.md。
- SourceImageIO.rawFileExtensions 统一常见品牌 RAW／DNG 的识别；ProjectStore 的发现、文件名及处理身份验证、应用的标定与重新定位选择器共用该列表。开放格式不改变 schema、RAW 处理身份、原 ARW 缓存或校准快照。应用包注册通用 RAW 图像类型，实际文件仍由统一列表和读取契约检查。含新 RAW 格式的项目需要支持该格式的应用；旧应用只接受 TIFF／ARW，不能因 schema 相同就视为能够读取这些新项目。
- TIFF代理缓存按标准化路径、size/纳秒mtime/inode和抽样版本定位，RAW沿用已有路径与修订契约。两者共用历史raw-v1缓存根及统一容量/期限管理，原RAW缓存无需重建。
- RAW缓存按标准化源路径、size/mtime修订与处理版本定位，命中不读原片全文SHA，继续校验代理完整性和损坏重建。旧无路径缓存首次使用重建，旧项由正常维护淘汰。未冻结来源的读取若失败且size/mtime已改变，重新获取身份并自动重试整个操作一次；再次失败交回现有错误流程。取消不重试，已冻结来源的导出/取样不自动切换原片。大小与mtime均不变的内容替换可能无法识别，这是明确接受的宽松边界。未知缓存文件、symlink和原片不被清理。
- PNG与TIFF/RAW代理共用本机系统缓存根 `studio.printroom.local.v3.3`、默认8GB/30天政策，启动、每小时、策略变化及新增资源触发后台维护。代理读者与清理继续使用共享/独占锁。自定义测试缓存保留独立限额。
- 旧卷旁存缩略图只在应用打开时按既有安全规则迁入系统缓存；失败保留原缓存。分层缓存、原片身份校验和取消机制均继续保留。

## 导出与交付

导出冻结有序目标、全卷受保护原路径、源身份、校准、卷级齿孔置白、帧参数/方向/裁剪及设置。每路只保留当前一张原图与有界行块；最多四路，独立于预览。真实 ICC 转换后嵌入目标 profile，像素与取样规则见 pipeline.md。

重名通过当前冲突回调询问覆盖、重命名或取消。覆盖先完整写入同目录私有临时目录，取消及原片保护检查通过才原子替换；拒绝覆盖才使用递增后缀。非交互调用仍采用无覆盖重命名。编码失败保留旧文件，结果按提交顺序返回。应用层保留结果数据用于汇总，ExportDialogController管理同一个原生设置sheet的草稿、运行与结束状态，ExportOptionsView底部原位显示进度和结果，不另开逐张结果面板。

随包只含两份当前派生电影LUT及必要ICC；仓库原始LUT与项目资产身份保留。LibRaw按LGPL 2.1选项保留源码与许可证，libdeflate 1.24按MIT许可内置源码静态构建（arm64/x86_64无需安装额外库），每个TIFF writer独占并复用压缩器与有界输出缓冲；应用原创部分采用GPL-3.0-only；见[第三方说明](../THIRD_PARTY_NOTICES.md)。旧项目和几何迁移继续保留。

## 旧项目兼容

结构、算法与几何分别版本化，当前分别为 schema9、density-v6、geometry2。支持旧项目读取不等于旧应用可以读取当前格式；损坏、未来版本或未知几何不能重置覆盖。

早期算法的470 CV反差pivot迁移为685 CV，已有非单位反差可能改变外观；旧版缺少CMOS时补Identity。当前运行使用烘焙LUT，保留已存Timing，不自动重做历史两卷的一次性补偿。旧Neutral选择回退Kodak 2383。旧输出p3或未知输出选项回退Display P3并同步profile身份。

几何版本1依赖每帧原尺寸及方向迁移，保持原构图；源缺失时保留旧值，等待恢复。首次覆盖旧格式前保存原JSON字节备份，按原项目情况使用算法、schema、几何或Neutral备份名；备份失败不覆盖。读取本身不写盘。


齿孔输出处理由SprocketWhiteningSettings/Context保存独立契约；CPU参考与Metal独立计算，具体公式仅见pipeline.md。主预览请求与显示缓存同时包含卷级设置和保护裁框，裁剪预览关闭后改变裁框仍使旧结果失效；缩略图缓存身份包含卷级设置。修改设置刷新整卷缩略图，撤销恢复设置，恢复本卷设置副本也恢复该字段。输出使用原有有界行块，透明度不写入项目、源代理或导出alpha通道。
